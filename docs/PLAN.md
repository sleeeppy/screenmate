# ScreenMate 구현 계획서

> 작성일 2026-11-12 · 대상: Windows 11 개인 PC (RTX 5070 Ti, 주 모니터 2048×1152 논리 해상도)
> 목표: 바탕화면 위에 MMD 캐릭터가 살아 움직이는 데스크톱 메이트. 모델은 사용자가 가진 PMD/PMX를 쓰고, 애니메이션은 직접 제작한다.

## 1. 모델 분석 결과 (실측)

받은 폴더 4개에 모델 파일 10개가 있다. 파서로 직접 읽어서 확인한 값이다.

| 모델 | 포맷 | 정점 | 본 | IK | 부여 | 강체/조인트 | 키(頭 y) | 다리 길이 | 팔 기본각 |
|---|---|---:|---:|---:|---:|---|---:|---:|---:|
| KAITO_DIVA風水着 | PMD | 7.5k | 105 | 6 | – | **0 / 0** | 19.7 | 10.4 | 39.2° |
| 鏡音リン_DIVA風水着 | PMD | 12k | 107 | 4 | – | **0 / 0** | 16.2 | 9.3 | 32.6° |
| 鏡音レン_DIVA風水着 | PMD | 5.9k | 95 | 4 | – | **0 / 0** | 16.4 | 9.0 | 36.8° |
| 始音カイコ_水着 | PMD | 8.6k | 113 | 6 | – | **0 / 0** | 17.9 | 10.1 | 33.7° |
| Sour式リン Black / White | PMX 2.0 | 41k | 373 | 6 | 16 | 186 / 273 | 16.2 | 8.9 | 37.7° |
| Sour式レン Black / White | PMX 2.0 | 36k | 263 | 16 | 16 | 65 / 41 | 16.7 | 9.3 | 38.6° |
| YYB式鏡音レン v1.00 | PMX 2.0 | 38k | 167 | 4 | 28 | 38 / 18 | 16.3 | 9.6 | 39.6° |
| Lat Kagamine Len v1.3 | PMD | 22k | 126 | 4 | – | **0 / 0** | 16.3 | 9.7 | 39.6° |

**계획에 영향을 주는 사실**

1. **표준 본 이름은 전부 있다.** センター, 上半身, 首, 頭, 腕, ひじ, 手首, 足, ひざ, 足首, 足ＩＫ가 모든 모델에 존재한다. 따라서 모션 하나를 10개 모델에 공통으로 쓸 수 있다.
2. **준표준 본은 PMD 5개에 없다.** グルーブ, 腰, 上半身2, 腕捩, 足D가 빠져 있다. 모션은 표준 본만으로 작성하고, 上半身2 트랙은 없으면 上半身에 합치는 리매핑을 둔다.
3. **PMD 5개는 물리가 없다** (강체 0개). 머리카락과 옷이 흔들리지 않는다. 보완책으로 이름 패턴(髪, ネクタイ, スカート 등)으로 본을 찾아 절차적 스프링을 거는 "라이트 스프링"을 둔다 (M6).
4. **팔 기본각이 32.6~39.6°로 모델마다 다르다** (모두 A포즈). VMD 회전은 기본 자세 기준이라 같은 모션도 팔 높이가 최대 7° 달라진다. 모델별 보정(아래 4.4)으로 맞춘다.
5. **크기는 거의 같다.** KAITO만 약 20% 크다. 화면 표시 크기는 頭 y 값으로 정규화한다.
6. **표정 모프 이름이 제각각이다.** 예: `ウィンク` / `ウインク` / `ｳｨﾝｸ`, `にこり` / `にっこり`. びっくり는 DIVA 린·렌과 Lat 모델에 없다. 따라서 감정 → 모프 별칭 테이블과 반각/전각 정규화가 필요하다.
7. **파일 이름이 깨져 있다.** Shift-JIS로 된 zip을 CP949로 풀어서 생긴 문제다 (예: `떮돶깏깛_DIVA븮릣뭶.pmd` → 원래 이름 `鏡音リン_DIVA風水着.pmd`). 거꾸로 변환하면 원래 이름이 100% 복원된다. 텍스처 파일명은 ASCII라 로딩 자체에는 영향이 없지만, 가져오기 단계에서 자동으로 고친다.
8. **Lat 모델은 내부 이름이 `Lat式改変リンβ_Nor`이다.** 표시 이름은 폴더 이름을 쓴다.

**이용 약관 (readme 확인)**

- **YYB, Sour**: 상업·R18·정치·종교 이용 금지. 개조 후 배포 시 원본 readme 동봉 필수. Sour는 "다른 식(式)으로 개조 금지".
  → 개인 PC에서 쓰는 것은 문제없다. **공개 저장소에 올리면 재배포가 되므로 저장소는 비공개로 둔다** (2026-11-13부터 `models/`를 커밋함, 0절). VRM 등 다른 포맷으로 변환하지 않고 원본 PMX를 그대로 렌더링한다.
- **DIVA風水着**: 제작 크레딧만 있고 이용 조건은 명시되어 있지 않다. 재배포하지 않는다.
- **Lat**: 폴더에 readme가 없다. 원 배포처 조건을 확인하기 전까지 개인 사용으로만 한정한다.
- 캐릭터(린·렌·KAITO)는 Crypton의 피아프로 캐릭터 라이선스를 따르므로 비상업 개인 사용으로 한정한다.

## 2. 스택 비교와 선택 이유

핵심 난이도는 창이 아니라 **MMD 런타임**이다. 필요한 기능은 PMX/PMD 파싱, SDEF 스키닝, IK, 부여 변환, 모프, 툰·스피어 재질, 그리고 Sour 린 기준 강체 186개와 조인트 273개를 돌리는 Bullet 물리다.

| 후보 | MMD 런타임 | 투명·클릭 통과 창 | 판단 |
|---|---|---|---|
| C# (WPF/WinUI) | 없음. 처음부터 구현해야 함 | 가장 깔끔 | ✗ 몇 달짜리 엔진 개발 |
| Swift (맥) | 없음 | 가능 | ✗ 맥은 당장 목표가 아니고 코드가 두 벌 |
| Rust + GPUI | GPUI는 2D UI 프레임워크. 3D, 스키닝, 물리 모두 없음 | 가능 | ✗ wgpu로 엔진을 직접 만드는 것과 같음 |
| Unity | MMD4Mecanim 등 오래된 도구뿐이고 FBX 변환이 필요 | Win32 호출로 직접 구현 | △ 무겁고 변환 과정에서 품질이 떨어짐 |
| three.js | MMDLoader가 r172에서 제거됨 (설치된 r187에는 CCDIKSolver만 남음). 후속인 `@moeru/three-mmd`는 아직 베타 | – | △ |
| **Babylon.js + babylon-mmd** | **PMX/PMD, SDEF, IK, 부여, 모프, VMD, Bullet(WASM) 모두 지원. 1.3.0 안정판, 2026-07 갱신** | 웹뷰에 담아 사용 | ✓ 렌더링 |
| Electron 셸 | – | `setIgnoreMouseEvents(forward)` 기본 제공 | △ 상주 앱으로는 무거움 (~250MB). 창 목록 수집에 FFI 필요 |
| **Tauri 2 셸** | – | Rust에서 Win32를 직접 호출 | ✓ 가벼움. 창 열거와 이벤트 훅이 자연스러움 |

**Tauri를 택하는 대신 감수할 점**

- 개발 환경에 Rust 툴체인과 **Visual Studio Build Tools (C++ 데스크톱 워크로드, 약 6GB)**가 필요하다. 지금 PC에는 둘 다 없다. WebView2(157)는 이미 설치되어 있다.
- Tauri에는 Electron의 `forward` 옵션(클릭은 통과시키면서 마우스 이동은 받는 기능)이 없다. 그래서 Rust에서 커서 위치를 폴링해 웹뷰로 보내는 방식으로 구현한다 (4.2).
- babylon-mmd의 멀티스레드 물리(MPR)는 SharedArrayBuffer가 필요하다. 처음에는 단일 스레드 물리(SPR)로 시작한다. 모델 한 개 기준으로 충분하다.

## 4. 핵심 구현 방식

### 4.1 투명 오버레이 창

- 주 모니터 전체를 덮는 창 하나를 쓴다. 처음엔 주 모니터만 지원하고, 다중 모니터는 M6에서 가상 데스크톱 전체로 확장한다.
- Tauri 설정: `transparent`, `decorations: false`, `alwaysOnTop`, `skipTaskbar`, `shadow: false`.
- Rust에서 HWND를 받아 확장 스타일을 추가한다.
  - `WS_EX_TOOLWINDOW`: Alt+Tab 목록에서 숨김
  - `WS_EX_NOACTIVATE`: 클릭해도 사용 중인 창의 포커스를 뺏지 않음
  - `WS_EX_LAYERED`
- 전체화면 앱(게임, 영상)이 실행 중이면 캐릭터를 숨긴다. `SHQueryUserNotificationState`로 감지한다.

### 4.2 클릭 통과 (가장 중요한 검증 대상)

```
[Rust 커서 스레드 60Hz] GetCursorPos → 창 영역 안이면 웹뷰로 'cursor' 이벤트 전송
        ↓
[웹 렌더 루프] 프레임을 그린 직후 커서 위치의 1px 알파값을 읽음 → hit 여부 판정
        ↓ hit 상태가 바뀔 때만
[Rust] set_ignore_cursor_events(!hit)
```

- 기본 상태는 "무시"(클릭이 아래 창으로 통과)이다. 캐릭터 픽셀 위에 커서가 올라오면 해제해서 마우스 입력을 받는다.
- 경계에서 깜빡이지 않도록 히스테리시스를 둔다. 해제는 즉시 하고, 다시 무시로 돌릴 때는 2프레임 연속으로 빗나가야 한다. 드래그 중에는 상태를 고정한다.
- 알파값은 1px만 읽으므로 GPU 지연이 거의 없다. 판정이 메시 모양이 아니라 실제로 그려진 픽셀 기준이라 머리카락이나 투명 재질도 정확하다.

### 4.3 좌표계

- 직교 카메라를 쓰고 1 월드 단위 = 1 CSS px로 맞춘다. 화면 y(아래로 증가)는 월드 y(위로 증가)로 뒤집는다.
- 모델 스케일 = `목표 키(px) / 頭 y`. 기본 목표 키는 260px이고 트레이에서 S/M/L로 바꿀 수 있다.
- DPI는 Rust가 물리 px 좌표를 보낼 때 모니터 스케일로 나눠 CSS px로 바꾼다.

### 4.4 모델 보정 (`calibration.ts`)

모델을 로드할 때 본의 기본 위치로 아래 값을 계산해 프로필에 저장한다.

| 보정 | 계산 | 용도 |
|---|---|---|
| `scale` | 목표 키 / 頭 y | 화면 표시 크기 통일 |
| `armOffset` | 기준각 37° − 모델 팔 기본각 | 腕 본 Z 회전에 더해서 팔 높이를 모델끼리 맞춤 |
| `legScale` | 다리 길이 / 9.3 | 걷기 보폭, 足ＩＫ 이동량, 점프와 앉기 높이 |
| `centerY` | センター y | 앉기·매달리기 시 골반 기준 높이 |
| `headBone` | 頭 본 | 쓰다듬기 판정 범위 (머리 위쪽 25%) |

### 4.5 물리

- PMX: babylon-mmd `MmdBulletPhysics`를 쓰고 중력은 MMD 기준(−98)으로 둔다.
- 화면에서 캐릭터를 빠르게 끌면 루트가 순간이동한 것처럼 처리되어 물리가 폭주할 수 있다. 그래서 루트 속도를 제한(프레임당 최대 이동량)하고, 텔레포트급 이동(모델 교체, 위치 초기화) 때는 물리를 리셋한다.
- PMD: M6에서 라이트 스프링을 추가한다. 이름 패턴으로 체인을 찾아 감쇠 스프링으로 회전을 지연시킨다.

## 5. 애니메이션 설계

### 5.1 제작 방식: 코드로 쓰는 키프레임

```ts
// src/motion/clips/idle.ts
export default defineMotion({
  name: "idle",
  loop: true,
  length: 120,                       // 30fps 기준 4초
  bones: {
    "上半身": [k(0, { x: 0 }), k(60, { x: -2, ease: "inOut" }), k(120, { x: 0 })],
    "首":    [k(0, { y: 0 }), k(80, { y: 6 }), k(120, { y: 0 })],
    "左腕":  [k(0, { z: 0 }), k(60, { z: -2 }), k(120, { z: 0 })],   // armOffset은 런타임에 자동으로 더해짐
    "センター": [k(0, { pos: [0, 0, 0] }), k(60, { pos: [0, -0.1, 0] }), k(120, { pos: [0, 0, 0] })],
  },
  morphs: {},
});
```

- 회전은 MMD 로컬 축 기준 오일러각(도)으로 쓴다. 이동은 `legScale`이 곱해진다. 보간은 VMD 베지어 4점으로 변환한다 (`ease: linear | in | out | inOut | 커스텀 [x1,y1,x2,y2]`).
- `compile.ts`가 이 정의를 `MmdAnimation`으로 바꾼다. 런타임에 VMD 파일이 필요 없다.
- `npm run export-vmd`로 같은 모션을 `.vmd`로 내보내면 MikuMikuDance나 MikuMikuMoving에서 열어 실제 모델로 확인할 수 있다.
- 사용자가 직접 구한 VMD도 상태별로 덮어쓸 수 있다 (`profile.json`의 `overrides`).

### 5.2 레이어 순서 (프레임당)

1. **기본 클립**: 상태 머신이 고른 클립. 전환 시 0.2~0.3초 크로스페이드.
2. **절차적 가산 레이어**
   - 숨쉬기: 上半身 X축 ±1.2°, 3.5초 주기
   - 시선: 커서가 400px 안에 오면 首:頭 = 4:6 비율로 분배. 좌우 ±35°, 상하 ±20°로 제한
   - 깜빡임: まばたき를 2~6초 랜덤 간격, 0.12초 동안
   - 매달림 흔들림: 드래그 속도의 반대 방향으로 下半身·足에 감쇠 진자 회전
3. **표정 레이어**: 감정 상태 → 모프 별칭 테이블 → 가중치 램프
4. **IK, 부여, 물리**: babylon-mmd가 처리

> ⚠ 검증 필요 (M1): 1~2번을 합치려면 babylon-mmd가 애니메이션을 계산한 뒤, IK를 풀기 전에 끼어들 지점이 필요하다. `IMmdRuntimeAnimation`을 직접 구현해서 컴포지트 애니메이션 위에 절차적 값을 더하는 방식으로 해결할 예정이다. 이 방식이 안 되면 절차적 레이어도 매 프레임 생성하는 동적 트랙으로 바꾼다.

## 6. 행동 (상태 머신)

```
          ┌──────── 랜덤 타이머 ────────┐
          ▼                             │
 [idle] ──→ [walk] ──→ [turn] ──→ [walk] ┘
   │  ↑                                     
   │  └── [land] ←── [fall] ←─ 발판 사라짐 (창 닫힘·최소화·이동)
   │                   ↑
   ├─ 마우스 다운 ─→ [hang] ─ 마우스 업 ─┘ (놓을 때 속도로 던져짐)
   │                   └─ 흔들기 / 3초 이상 ─→ [hang_struggle]
   ├─ 머리 클릭 ─→ [pat] ─→ idle
   ├─ 몸 클릭 ─→ [poke] ─→ idle
   ├─ 창 모서리 도달 + 확률 ─→ [sit_edge]
   └─ 10분 무입력 ─→ [sleep]
```

- **body.ts**: 캐릭터 루트를 점 하나로 보고 물리를 계산한다. 중력 2400px/s², 착지 시 탄성 0.15, 마찰을 적용하고, 던질 때 속도는 최대 3000px/s로 제한한다.
- **발판**: 작업표시줄 상단 + 보이는 창들의 위쪽 테두리 구간. 위에서 아래로 떨어질 때만 충돌한다(아래에서 올라갈 때는 통과).
- **창 위에 앉았을 때**: 그 창이 움직이면 같이 따라간다. 창을 빠르게 흔들면 떨어진다.

### 6.1 창 발판 수집 (`platforms.rs`)

1. `EnumWindows`로 최상위 창을 나열하고 아래 창은 제외한다.
   - 보이지 않는 창, 최소화된 창
   - `DWMWA_CLOAKED`인 창 (다른 가상 데스크톱 등)
   - 툴 윈도우, 자기 자신
2. `DWMWA_EXTENDED_FRAME_BOUNDS`로 그림자를 뺀 실제 창 영역을 얻는다.
3. Z순서대로 위 창이 덮고 있는 구간을 빼서, 실제로 보이는 위쪽 테두리 구간만 남긴다.
4. `SetWinEventHook`(창 위치 변경, 포그라운드 전환, 최소화)이 올 때만 다시 계산하고 30ms 단위로 묶어서 웹뷰로 보낸다.
5. 작업표시줄 위치는 `SHAppBarMessage(ABM_GETTASKBARPOS)`로 얻는다.

> 구현에서 바뀐 점 (M5): 이벤트 훅 대신 **폴링**(평소 150ms, 캐릭터가 창 위에 있을 때 33ms)으로 바뀐 경우에만 보낸다.
> 3번 가려짐 계산은 Rust가 아니라 웹뷰 `behavior/platforms.ts`(순수 TS, Node 테스트)에서 한다. 작업표시줄은 기존처럼 작업 영역 바닥으로 처리한다.
> macOS도 같은 구조로 지원한다 (`CGWindowListCopyWindowInfo`, 레이어 0 창만, 화면 기록 권한 불필요).

## 7. 모델 가져오기와 관리

1. 트레이 → "모델 가져오기…" → 폴더 선택 (zip 지원은 M6).
2. Rust가 파일명을 복원한다. CP949로 인코딩한 뒤 Shift-JIS로 디코딩해서 유효하면 원래 이름으로 바꾼다.
3. 폴더 안의 `.pmx`/`.pmd` 파일을 하나씩 모델로 등록한다. DIVA 폴더는 4개, Sour 폴더는 Black/White 변형으로 묶어서 등록한다.
4. `%APPDATA%\ScreenMate\models\<id>\`로 복사하고 readme도 같이 보관한다.
5. 처음 로드할 때 babylon-mmd의 **BPMX**(최적화된 바이너리)로 변환해 캐시한다. 다음부터는 이 캐시로 빠르게 로드한다.
6. 보정값, 모프 매핑, 물리 사용 여부를 담은 `profile.json`을 자동 생성한다. 직접 수정할 수도 있다.
7. 웹뷰는 `mate://models/<id>/...` 커스텀 프로토콜로 파일을 읽는다. 경로가 모델 폴더 밖으로 나가는 요청은 차단한다.

## 10. 현재 상태 (2026-11-13)

**M0~M5 완료, M6 진행 중 (모션 완료).** 다음은 M6의 PMD 라이트 스프링·다중 모니터·전체화면 숨김·자동 시작·설치 파일.

### 성능 (Sour 린 Black, 대기 상태, 개발 빌드)

| 항목 | M1 검증 버전 | 현재 |
|---|---:|---:|
| CPU (1코어 기준) | 18.8% | 9.2% |
| 전용 메모리 합계 | 634MB | 441MB |
| GPU 프로세스 | 379MB | 192MB |
| 캔버스 | 2560×1440 | 438×487 |
| 프레임 | 상시 ~72fps | 대기 28.8 / 활성 72fps |

바꾼 것
- 캔버스가 화면 전체가 아니라 캐릭터 주변 상자만큼만 있고 CSS transform으로 따라다닌다 (`stage/followBox.ts`).
- 렌더 루프를 직접 돌려 그리는 프레임에서만 `beginFrame()`을 부른다. `runRenderLoop`은 건너뛴 vsync에도 델타를 갱신해서 물리·애니메이션이 2~5배 느려지는 문제가 있었다.
- 주사율의 정수 배수로 프레임을 조절한다 (`stage/framePacer.ts`). 커서가 가까이 있거나 물리가 가라앉는 동안만 활성 fps.
- 물리는 실제 경과 시간 기반 1/60초 고정 스텝 (렌더 fps와 무관).
- Rust 커서 폴링이 창 위치를 캐시하고, 관심 영역 안에서 커서가 움직일 때만 이벤트를 보낸다.
- 텍스처는 최대 1024로 줄여 올린다 (2048→1024 박스 필터).

### 렌더링 수정
- 텍스처 알파를 전부 끄던 처리를 없앴다. babylon-mmd 기본 알파 평가를 쓰고 캔버스를 premultiplied alpha로 바꿨다. 눈·안경·옷 오려내기가 정상으로 보인다.
- 카메라를 MMD 기본 시점(-z → +z)으로 바꿨다. 이전에는 화면 오른쪽이 월드 -x라 M4 걷기 방향이 뒤집힐 상태였다.
- 조명을 babylon-mmd 권장값으로 바꿔 툰 텍스처 없는 PMD가 하얗게 날아가지 않는다.
- MMD 윤곽선(엣지)을 켰다.
- babylon-mmd 1.3.0 PMD 로더 버그(루트 본 부모 -1 → undefined)를 `vite.config.ts` 변환 플러그인으로 패치했다. Lat 모델이 이것 때문에 안 열렸다.

### M3 모션 (2026-11-13)
계획(5.1)과 달리 DSL을 babylon-mmd `MmdAnimation`으로 바꾸지 않고 **우리 슬롯에서 키프레임을 직접 계산**한다.
크로스페이드·모델 보정·절차적 레이어를 한곳에서 처리하기 위해서다. 슬롯이 `beforePhysics()`의 애니메이션 자리에서
본·모프에 값을 쓰므로 부여 변환·IK·물리가 그대로 따라온다 (5.2의 검증 필요 항목 해결).

- 흔들기: 발을 1.45만큼, 앞쪽(40%)에서 가장 높이. 팔 흔들기 ±22°.
- **걸음마다 끊기던 것**: 흔들기 앞뒤 곡선의 양 끝 속도가 0이라 발을 뗄 때 디딤 속도(뒤로)에서 앞으로 확 뒤집히고(0.259 → -0.064/프레임),
  디딜 때 멈칫했다. 양 끝 기울기를 디딤 속도에 맞춘 3차 에르미트로 바꿨다. 들어 올림도 발을 뗄 때 기울기가 무한대였던 곡선(s^0.75)을
  유한한 곡선으로 바꾸고, 밀기 끝 발목 상승 속도와 이어지게 했다.
- **멈출 때 발 미끄러짐**: 걷기 시간이 끝나도 두 발이 몸 아래에서 엇갈리는 프레임(8.5, 23.5)까지 마저 걷고(최대 0.6초) 선다.
  들린 발만 내려놓으면 되어 앞뒤로 벌린 발이 미끄러지지 않는다 (`Actor.canStopWalking`, `isPassingFrame`).
- 테스트: 멈춤 대기, 엇갈림 프레임의 발 위치, 발 뗄 때·디딜 때 속도 방향 유지.

### 모델 불러올 때 리본·넥타이가 늘어나던 문제 (2026-11-13)
- 원인: 새 모델을 놓을 때 물리 기준점(PHYSICS_TRAVEL)을 이전 모델 배율(첫 로드는 1)로 계산해, 다음 프레임 제 위치로 옮길 때
  강체가 순간이동으로 보고 리본·넥타이·머리카락을 화면을 가로질러 늘렸다 (3~4프레임).
- 고침: 위치·기준점 모두 새 모델 배율로 계산, 로드 직후 물리 리셋, 텍스처·셰이더 준비 + 0.35초 물리 안정까지 숨겼다가 보여 준다
  (최대 2초). 불러오는 순간 연속 캡처로 확인.

### M6 모션 (2026-11-13)
- 새 클립: `hang_struggle`(버둥거리기), `idle_look`(두리번), `idle_stretch`(기지개), `sit_edge`·`sit_floor`(걸터앉기·바닥 장좌),
  `sleep_edge`·`sleep_floor`(앉아서 졸기). 앉기 넷은 `clips/sit.ts` 한 빌더로 만든다 (센터를 엉덩이 높이 9.5만큼 내림, 다리 IK 끔).
- 행동 (`behavior.ts`, 앱에서만 `variety` 켬 — 기존 테스트의 고정 난수 순서와 섞이지 않게):
  - 들고 3초가 지나거나 잡은 손의 평균 속력이 1800px/s를 넘으면 버둥거림 (진자 흔들림으로 재면 빠르게 흔들수록 작아져 손 속력으로).
    최소 1.2초는 계속한다.
  - 서 있기가 끝나면: 창 위 30% 걸터앉기, 바닥 6% 장좌, 14% 두리번, 8% 기지개, 나머지 걷기. 앉기는 8~18초, 앉은 채 창을 따라간다.
  - 10분(`sleepAfter`) 동안 입력(커서 근처·클릭·끌기)이 없으면 그 자리에서 앉아 존다. 입력이 오면 깬다.
  - 앉으면 머리 높이(키 0.42배)로 쓰다듬기 판정·시선 기준을 낮춘다. 걸터앉으면 캔버스 상자를 아래로 늘린다.
  - 트레이 미리보기에서 앉기 모션을 고르면 앉은 상태로 보여 준다.
- 기지개는 처음에 팔을 옆으로(Z) 들어 체조처럼 보였다 → Z로 곧게 내린 뒤 X로 앞→위 165°. 기본 자세 팔이 37° 아래라
  53°만 내려야 한다 (75° 내리면 몸 안쪽으로 넘어가 머리 위에서 손이 엇갈렸다).
- 테스트 6개 추가 (버둥거리기 두 경우, 두리번·기지개, 창 위 걸터앉기와 따라가기, 졸기와 깨기, 앉은 머리 쓰다듬기).

### 창 위에서 창을 옮길 때 끊김 (2026-11-14)
- 측정 (60Hz로 움직이는 tkinter 창 위에서 프레임별 발 이동 속도): 원래 창 위에 서 있으면 30fps, 60fps일 때도
  폴링이 33ms라 프레임 절반(초당 35~52프레임)은 안 움직이고 나머지가 두 배로 움직였다 (뚝뚝).
- 고침: 창 위에 있으면 창 목록을 8ms마다 읽고(`platforms.rs`), 서 있는 창이 움직이는 동안은 60fps(`activity` interact).
  창 위치 샘플 간격으로 창 속도를 어림해 그 속도로 움직이고 오차는 40ms 반감기로 메운다(`followWindow`). 가만히 있던 창의 첫 변화로는
  속도를 어림하지 않는다 (한 번에 옮긴 창을 2400px/s로 오해해 100px 넘쳤다). 반 키 넘게 튀면 바로 옮긴다.
- 결과: 안 움직이는 프레임 0, 같은 속도 구간 프레임별 속도 편차 ±117~131 → ±13~35px/s. 테스트 1개 추가.

### 남은 것
- 걸터앉기는 창 위에서 다리가 테두리 아래로 늘어진 모습을 화면으로 아직 확인하지 못했다 (미리보기는 바닥에서 한다).
- Sour 린 치마는 서 있을 때 아직 미세하게 떨린다. 더 줄이려면 치마 강체 질량 하한(실험에서 평균 약 35% 감소)이나 조인트 완화가
  필요한데, 머리카락 등 다른 강체 느낌도 바뀌어 보류.
- DIVA 렌은 팔 기본각 보정이 거의 없어(0.19°) 걸을 때 앞으로 나가는 팔이 다른 모델보다 높아 보인다.
- 물리 스텝을 1/120으로 바꾼 뒤 CPU 사용량은 아직 다시 재지 않았다.
- 해석적 다리 IK는 DIVA 린으로만 앱에서 확인했다. 腰キャンセル 본이 있는 Sour·YYB에서도 발이 목표에 닿는지 확인 필요.
- 걷기·매달리기 다듬기는 Rin(DIVA) 한 모델로만 화면 확인했다. 다른 모델(Sour·YYB)에서 발이 바닥을 뚫거나 뜨는지 확인 필요.
- 떨어지기·착지·쓰다듬기·찌르기는 아직 첫 버전 그대로.
- M5 Windows 실기 확인: 메모장 창에 떨어뜨리기·옮기기·흔들기·닫기, 가상 데스크톱 전환, 고DPI 배율에서 테두리 위치.
- 앉기(sit_edge) 모션이 아직 없어 창 끝에서도 서 있는다 — M6 모션.
- BPMX 캐시: PMX 로드가 이미 0.3~0.4초라 효과가 작아 보류. 필요하면 M6에서.
- 트레이 메뉴(모션 미리보기 포함)는 빌드·생성까지만 확인했고 클릭 동작은 아직 직접 눌러보지 않았다.
- 무릎·발목 굽힘은 정면 직교 카메라라 화면에서 거의 안 보인다.
- YYB 렌 반바지·벨트 일부가 반투명 재질(알파 0.2~0.7)이라 바탕화면이 살짝 비쳐 보일 수 있다. 캐릭터가 작게 그려져 작은 밉맵을 쓰는 영향도 있다. M6 재질 정리 때.
- 행동에서 들린 채 오래 있거나 세게 흔들면 버둥거리기(hang_struggle) — M6 모션.
- DIVA 렌은 びっくり 모프가 없어 surprise 표정이 비어 있다 (대체 후보 瞳小도 없음).
- 모델 분석용 Python 파서는 아직 `tools/`로 옮기지 않았다.
